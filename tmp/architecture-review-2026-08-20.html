1. Instrument Connection Adapter

Extract duplicated instrument connection logic from views into a shared adapter hook

  • views/InstrumentMonitorView.tsx

Problem

Both TraverseView and InstrumentMonitorView contain ~150 LOC of duplicated instrument connection logic: serial port enumeration, BLE scanning, NTRIP connection, observation subscription, status polling. The sidecar API call pattern is copy-pasted with slight variations.
Deletion test: Deleting from either view concentrates complexity — confirming a real shared module.

Solution

Extract a useInstrumentConnection() React hook encapsulating the full connection lifecycle: port scanning, connect/disconnect, observation subscription, status polling, and cleanup.

Benefits

Locality: All instrument logic in one module. Bug fixes propagate automatically.
Leverage: One mock of window.metardu.instrument tests all connection paths.
Testability: Hook unit-tested with fake sidecar. Integration tests verify observation→state flow.

  • main/index.ts (IPC handler)

Problem

INTEGRATION_EXPORTERS uses IntegrationExporter<any, any, any> — type safety erased at registry level. ExportPanel dispatches on format string with no compile-time guarantee.

Solution

Replace with a discriminated union registry keyed by format literal. ExportPanel does switch (format) with exhaustive checking. Adding a new exporter: implement interface + add one line to registry.

3. Cross-Import Event Bus

Worth Exploring

  • views/*.tsx (5 views consume)

Problem

CrossImportPayload is a discriminated union growing by one variant per new cross-view data flow. Currently 5 variants. Forgetting to null the payload after consumption causes infinite re-render loops.

Solution

Replace single-state crossImport with a CrossImportBus<Events>. Views subscribe('cogo_points', handler) and emit('traverse_results', payload). Bus handles cleanup automatically.

Problem

SurveyCanvas is a 730-line god component handling points, lines, polygons, contours, TIN, ellipses, legend, north arrow, scale bar, zoom/pan. Every new visualization makes it harder to test.

Solution

Decompose into composable layers: CanvasBase, PointLayer, LineLayer, PolygonLayer, ContourLayer, TINLayer, EllipseLayer, LegendOverlay. SurveyCanvas becomes a thin composition wrapper.

Problem

Fee scales exist in two places: renderer's fee-scales.ts (8 countries) and country-config (separate copy). Renderer version is more complete but engine can't use it — violating "engine owns the math."

Solution

Move fee scales into country-config as a feeScales property. Engine's invoice module consumes them. Renderer imports from @metardu/country-config.

🏆 Top Recommendation

Start with #1: Instrument Connection Adapter

Highest leverage — eliminates ~300 LOC of duplication across 2 views, creates a single testable seam, and immediately benefits 3 views. The deletion test confirms it concentrates real complexity, and the hook pattern is well-established in React.

Why not #2 (Exporter Registry)? — Also strong, but the any types are a deliberate choice per ADR-0005 for heterogeneous input types. Worth doing, but lower immediate ROI.

Why not #3 (Cross-Import)? — Current pattern works for 5 events. An event bus adds indirection without proportional benefit at this scale. Revisit at 10+ cross-view flows.
